# External Mesh Network Explorer

## Desired experience

Every public publisher can be browsed by display name, public member/axon identity, declared topics and capabilities. Blank search explores public nodes, exact topic lookup narrows candidates, and richer name/full-text search is a later local index over independently retrieved signed cards. Search is a priority hint, never a whitelist: default public interest is all topics. The network automatically joins eligible public Axons without a per-peer dialog after open-exchange consent. Auto-join is bounded, revocable, and independent from private compute authorization. Internal Mesh membership is never inferred from a public listing; invited members can browse authorized private devices and capabilities separately.

## Decentralized index

External Kademlia uses /roots/external/kad/1. Provider keys are namespaced:
- roots/external/browse/1/<shard> (8 initial shards, stable hash of public Peer ID)
- roots/external/topic/1/<normalized tag>
- roots/external/node/1/<peer-id> (signed value, not provider lookup)

Provider results are hints, not authenticated claims. Fetch the corresponding node card and verify its public key maps to the expected Peer ID, signature, canonical payload, expiration, and that a searched tag really occurs in the signed card. A signature proves control of a key, not the asserted name, expertise, content accuracy or membership. Reject malformed, expired, oversized or mismatched records. Prefer newer valid revisions; don't equate DHT response count with total population. Current DHT browse is bounded sampling, not exhaustive enumeration; the durable directory below supplies ordered browsing independently of the DHT. Increase shard count and use rotating subsets, independent bootstrap paths, and cached signed catalogs as the network grows. No compulsory central registry, tracker or account service.

The first signed directory card has version, peer_id, display_name, sorted unique public topics, revision (Unix seconds), expires (Unix seconds), and capabilities=["directory"]. It is NOT the final public .axon format. The signature covers domain bytes "roots.external.node.v1" plus NUL plus the exact canonical JSON body generated in schema field order. Envelope contains hex body, public_key (libp2p protobuf) and signature. Maximum 8192 bytes. Owner signature verification is independent of Kademlia record replication. Public topic tags are explicitly supplied in this prototype; future defaults derive from the External Mesh publication projection, never private Tree or prompts.

## Automatic joining (next integration gate)

Discovery -> verify signed public node/member/Axon descriptors -> persist candidate -> check local block, consent, quota and compatibility -> schedule connection -> authenticate a public exchange session -> commit durable binding and inventory checkpoint -> continue missing items on future encounters. Never mark a directory candidate "bound" before the exchange handshake. The public binding carries no private GPU, knowledge, relay or invitation grant. Use a stable member identity and portable signed .axon, with expiring separate route records; map BLE and internet endpoints to the same signed member and Axon only after key authorization. Explicitly public redistributable content only, never automatic import into Internal Mesh. A user may promote an item or request a private invitation later.

Use separate queues for discovery and synchronization; small random and novelty-weighted exploration across categories, retain all eligible public descriptors within cache limits, prioritize rare/missing fragments, cap concurrent dials and total bytes, apply jittered backoff. Start with at most two concurrent internet exchanges, configurable storage and mobile battery/data budgets, and pause on toggle-off or OS conditions. A blocked member is never rejoined unless unblocked. Do not scan all IPs or treat a routing node as a publisher.

## First implementation

The Android Explorer lists already bound nearby Axons and fetches verified public internet directory cards through Rust JNI. CLI can serve a routing node, publish a directory card and browse/search. Search is exact tag or blank browse, up to 48 candidates, bounded query windows; incomplete searches are visibly partial. No seed infrastructure is provisioned by this change. Directory-only cards do not establish automatic Internet bindings; the existing default-on BLE service remains the only automatic public data exchange. Public Internet .axon synchronization, durable candidate cache, full-text discovery, member identity unification and private authorized capability browsing are subsequent gates. Android, Windows and Rust build/interoperability tests still required.

## Durable browsable Mesh (2026-11-28 decision)

Use existing Axon exchange, signed descriptors, Whirlwind and Kademlia; no separate Mesh Spine, convergence scoring, connectivity weight, GGUF routing layer or required blockchain. The public directory is an index of references, not a copy of every contributor or of their Tree. A client holds bounded local references and obtains pages from other directory holders. Existing archive exchange remains independent and unchanged.

### Publication policy

All External Mesh contributors publish their public Tree and Branch descriptors, public Axon relationships, topics, languages, manifests, publisher references, availability and public capabilities by default as part of disclosed External Mesh participation. No per-object approval for already-public resources. This does not promote Internal Mesh material, private captures, credentials, private routes, local aliases, inference grants or unapproved redistributable content. Existing full Root graph consent is not bypassed; publication scope determines what is public before directory projection. Relationships are one publisher's signed claims unless both endpoints attest. A public link does not create a binding or grant permission.

### First increment: public Axon footprints

Reuse the existing authenticated P-256 REP identity (SHA-256 of DER SubjectPublicKeyInfo), not the unrelated libp2p directory identity. Add optional `footprints_v1` in the existing bind/bound JSON; no extra round trips or payload encryption. A page has at most nine records (own card first, up to eight sampled previously verified cards); old peers ignore the unknown field. Each independently signed card contains `id`, `revision` (Unix milliseconds, nonnegative, at most five minutes ahead), `links` (at most eight unique ascending lowercase 64-hex public Axon IDs, excluding self), `key` and `sig` (standard padded Base64 DER SPKI and DER ECDSA signature). Sign UTF-8 bytes exactly: ASCII domain `roots.public.footprint.v1\n`, id, LF, decimal revision, LF, each link followed by LF. Key must be canonical P-256 SPKI and hash to id. JSON field order does not matter. The first card must match the authenticated peer before accepting forwarded cards. Verify every card, ignore malformed ones, prefer higher revision, reject future-dated cards and self cards. At equal revision retain existing record, never treat it as a new claim. Blocked contributors excluded from exchange and browsing. No private aliases, addresses, route, key material other than public verification key, or content bytes.

Keep up to 4096 latest signed cards per installation in a local directory independent of Tree and GGUF. This is a bounded best-effort cache, not custody or a global census; show that explicitly. A historical footprint survives disconnect/restart but does not prove present reachability. Sample up to eight forwarded cards per encounter; no additional transfer phase. When available, display saved footprints in ID order with pages and allow users to inspect linked IDs without automatically connecting. Some advertised links may not yet have locally retained cards. This protocol supplements existing DHT discovery; identities are not merged until independently authorized. Use ordinary TLS and current secure BLE connection, no added payload cipher.

### Remaining gates

1. Add signed contributor descriptors with public manifest, topic/language, availability and capability references and versioned pages; preserve existing publication policy.
2. Add remote `directory.page` and `directory.get` to the authenticated public exchange, with bounded cursors, explicit snapshot/revision and durable progress. Page by contributor ID; follow signed region/page pointers and public relationships, even via a replica. Support backward and forward UI navigation.
3. Publish addressable page digests and providers using existing DHT/Whirlwind; retain replicated, durable pages independently of expiring live routes. Use Merkle comparison/delta exchange and adaptive archive sizing where appropriate. Preserve sparse independent routes; no full directory requirement per node. Design durable custody acknowledgments, repair, capacity/failure-domain diversity, signed withdrawal and conflict rules before claiming persistence guarantees.
4. Unify REP and libp2p identities using an explicitly signed binding; enable Internet public exchange, direct lookup and `root://` resolution. Optional HTTPS gateway later.
5. Measure discovery coverage, hop count, duplicate rates and bytes before introducing specialized weak-link optimization. Optional blockchain anchoring of signed provenance/relationship roots later, never required for discovery.

Acceptance: three contributors in a chain discover a remote signed card without direct binding; forged, mismatched, oversized or stale-revision cards cannot overwrite a valid record; no private capture/route/grant in directory; cache survives reboot; old peers still transfer archives; browse can resume through replicated pages while origin offline; partitions and unknown regions are labeled partial, not counted as a complete global census. A live connection to an offline device is impossible; a public record may remain browsable through replicas. No claim of guaranteed global enumeration until an explicit registered snapshot and custody model exists.
