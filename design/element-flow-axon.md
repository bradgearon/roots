# Element Flow and .axon subscriptions (v1)

## Observer
The Android intelligence engine is still dense, CPU-backed llama.cpp at b11960. The optional Gemma flow analyzer also supports the selected Qwen model where the named tensors exist. The native evaluation callback samples one last-token row from the last prefill batch and up to eight early decode evaluations. It observes `ffn_geglu`, `ffn_swiglu` or `ffn_gate_par` (gated FFN channels before down projection), `attn_post_norm` and `l_out`. Groups contain 32 contiguous channels. Attention-output and residual groups are **not** attention heads. Unsupported tensor shapes/types are skipped and counted. The callback never changes tensor values or suppresses model execution. Profiling is opt-in because callbacks can split computation graphs and increase latency.

For group g, per-tensor energy share is sum(x² in g)/sum(x² in tensor row). Store only aggregate means, counts, exact GGUF SHA-256 and task name (general sample, poetic selection, poetic resolution). Prefill and decode profiles are separate; use decode if observed, prefill otherwise. Exponential moving average .8 previous + .2 new. No text, token IDs, raw activations, hidden states, outputs, or weight values are stored. Group shares across layers are normalized for reporting, not causal contributions. No semantic or causal labels are inferred. The initial structural address is exact model + layer + family + group.

On subsequent observed requests select up to 16 strongest FFN groups from the task baseline. Use verified GGUF tensor metadata to locate corresponding gate/up quantized rows and issue POSIX WILLNEED hints, at most 4 MiB. This is advisory OS page-cache preparation after model load and before request computation, not guaranteed I/O, sparse execution, or proven acceleration. Dense execution remains unchanged; no attempt is made to read contiguous down-projection columns. Report actual hinted bytes and last top-16 overlap. Runtime observations are simultaneous with the dense inference callback; conditional next-layer lookahead, model sharding, and sparse kernels are future work.

## Local .axon policy
Mesh UI: paste one or more current roots:// invitations, Bind / edit .axon, choose model and operation, enter one topic per line. Optional mapping: `music | 7:12,8:2` associates explicit FFN group addresses with that topic. Addresses are model-version-specific and are hypotheses, not learned meanings. Use `*` to subscribe to all other topics; absent it, unmatched topics are excluded. A group may be mapped to at most one topic. The private file subscription.axon binds peer certificate SHA-256 identities, exact model hash, operation, and topic mappings. Peer endpoints and session tokens are saved separately in subscription.axon-access under noBackup, encrypted with an Android Keystore AES-GCM key and authenticated to the exact bound identity set. Test, Receive, and runtime arming reuse that access when the invitation box is empty. Explicit invitations override the saved set and refresh access only for approved identities; an invalid explicit invitation never falls back to older access. Topic/model edits preserve saved connections, and removing the binding removes saved access. Older policy-only bindings need one current invitation to save access. A peer listener restart still requires its new invitation; saving a token does not extend the peer's grant. This is a persistent local policy and saved access, not automatic radio pairing or new transport.

At sync, build a knowledge-demand prior from matched local-language Tree records, the current decayed GGUF wave priority, and a floor for unobserved topics. Normalize it across subscribed topics. Sum measured FFN mass for each explicitly mapped topic and normalize across those mapped groups only. When measured mapped flow exists, blend 50% local knowledge prior and 50% normalized mapped element mass; otherwise use knowledge prior alone. This is a heuristic **allocation** based on observed activity, not a measure of actual unmet computational need. View current flow allocation displays percentages. Incoming offered items must match a subscribed topic, with longest topic match and explicit wildcard fallback. Weighted fair scheduling assigns up to 32 missing items per sync by virtual finish time (served+1)/share; rarest first, demand, language, then hash within a lane. Empty lanes do not consume capacity. Percentages describe item scheduling, not bytes; finite offers/failures change realized shares. Content ID, advertised topic and language are checked before insertion. The peer sees only normal inventory/want traffic, no local activation profiles, wave weights, or private branch text. Existing ordinary Mesh receive remains available with Axon unchecked.

First run builds baseline; second reports prior prediction overlap and cache hint bytes. Compare enabled/disabled results and latency on-device before making any speed or fidelity claims. Bind .axon to current invitation(s), specify topics and optional observed group addresses, view percentages and receive. Check no unmatched offers are transferred. Test fresh invitation from same pinned device; unrelated identities must be rejected. Existing LAN invitation transport; Wi-Fi Aware, automatic reconnect, distributed inference and dynamic next-layer prediction are not implemented.

Host allocation checks exercise normalized percentages, cold start, rarity, filtering, uniqueness and fallback. Android/NDK device build and native activation measurements remain required.
