# Roots Encounter Protocol — REP/1 experimental Android profile

A Post continuously advertises one connectable BLE service. A passing Roots device discovers the service using a low-power filtered scan, reads the dynamic LE L2CAP PSM from a GATT characteristic and opens a bidirectional Bluetooth LE connection. No IP, access point, Internet service, Bluetooth bonding or LAN invitation is needed. A Post can also be an Android phone.

## Publication and authorization

A user enables Open Exchange once and chooses Publisher or Passerby. All explicitly published knowledge topics are then eligible for both directions and for forwarding. There is no per-encounter confirmation or topic gate. The UI must clearly state that copies may leave the device permanently. The native Tree's current LAN graph catalog includes raw captures and is not an appropriate public catalog: REP/1 reuses the explicit Mesh publication catalog only. A future public graph projection can publish user-authorized graph relationships and source links without exporting the raw captured Tree. Received content is untrusted and is not runtime authority.

## Radio

Service UUID 7d6f6f74-732d-4c45-9a01-000000000001; readable PSM characteristic 7d6f6f74-732d-4c45-9a01-000000000002. PSM is two unsigned big-endian bytes, dynamic for the lifetime of the listening socket. Use LE CoC (not classic RFCOMM); reject missing, zero or out-of-range PSM. Advertisement contains only the service UUID, no user identifier, MAC binding, topic or data. The Android profile starts with Android 12+ and a user-started connectedDevice foreground service; Android and device power-management policies still apply. GATT-only fallback, passive PendingIntent scanning, boot restart and firmware are future work. No wake lock, exact alarm, Internet permission addition or Wi-Fi routing.

## Wire contract (prototype, not frozen)

On the byte stream use big-endian 32-bit lengths. Client sends a hello then server sends a hello, each limited to 1024 bytes. Hello: 32-bit magic 0x52455031, length-prefixed X.509 SubjectPublicKeyInfo persistent P-256 signing key, length-prefixed ephemeral P-256 key, 32-byte random nonce. Hash SHA-256 of ASCII Roots REP/1 handshake and length-prefixed client and server hello, in order. Each side signs role byte (1 client, 2 server) plus transcript hash with SHA256withECDSA. Exchange length-prefixed signatures (max 256 bytes), client first. Verify both proofs before any knowledge. ECDH on ephemeral keys; HKDF-SHA256 extract using transcript hash as salt, expand ASCII Roots REP/1 client to server or Roots REP/1 server to client plus 0x01, 32 bytes each. AES-256-GCM, nonce 4 zero bytes plus big-endian uint64 sequence starting at zero for each direction; AAD handshake label plus nonce. Encrypted frame length includes 16-byte tag; plaintext 1–65536 bytes. Terminate on any failure. This is experimental composition, not Noise/TLS compliance and not independently audited. A first-contact self-authenticated identity does not prove ownership of a named physical Post or protect against identity substitution at first contact; only a previously known key can be recognized. No stable personal identifier in advertisement; peer-visible signing identity is linkable across encounters. Private keys remain Android Keystore backed.

Inside encrypted records, use UTF-8 JSON in the first implementation to reuse MeshItem canonical content hashes; CBOR is a later version. Client sends bind, server answers bound. Client pulls and releases, then server pulls and releases. Each pull issues inventory with saved root and after cursor; responder returns root (SHA-256 of sorted concatenated 64-character content IDs), up to 32 sorted IDs and more flag. Different root resets cursor. Request want with an offered id, answer data with exact verified MeshItem JSON, ack only after durable Tree store. Release ends a direction. Each direction bounded to 64 examined IDs, eight fetched items and three inventory requests; timeout closes the connection. On reconnect, durable cursor resumes after verified items; end of inventory resets cursor for subsequent cycles. Each peer's .axon stores peer public-key digest, public wildcard scope, remote root, cursor and encounter count under app-private noBackup storage. No coordinates, MAC or private runtime grant. Tree clear cancels active sync; subsequent cycles recheck missing items.

## Qualification before merge

Two phones with Bluetooth on and Wi-Fi/cellular off, one Publisher and one Passerby, each with a distinct explicitly published remembrance. Verify bidirectional delivery, same-source link retained, repeat encounter after process restart, resume after breaking radio, no duplicate Tree observations, no private raw captures or LAN invitation credentials sent, and stop/revoke. Test Bluetooth disabled, denied permissions, screen off, oversized or malicious data, corrupted records, repeated reconnects, key mismatch, full binding store. Benchmark discovery latency, power draw, airtime and publisher concurrency on real hardware. Independent cryptography review and firmware interoperability are required; no production security or battery-life claim.

## Android app entry point

Roots Mesh > Open Bluetooth exchange. Write a remembrance on each phone first. Start Publisher on one phone and Passerby on the other. Grant Nearby devices permission. Both roles send and receive: their distinction is radio discovery only. No manual peer invitations. Disable Wi-Fi and cellular during acceptance; Bluetooth must remain on. A persistent connected-device foreground service handles the session with low-power filtered scanning or connectable advertising. Android may stop or throttle the service. Stop from the screen or notification; switch roles only after stopping. The service requests sticky process restart while enabled, but not boot startup. The app shows retained binding count and last encounter result. The existing saved LAN Axon remains unchanged; separate encounter Axons are not yet editable with the existing Axon editor. No private prompt/runtime inference grant is implied.

Prototype limitations: one encounter at a time, 30-second transient radio retry backoff, up to 25 seconds per data session, no GATT-only transfer fallback, no dedicated Post firmware or iOS implementation yet. The explicit public publication catalog currently uses the existing legacy 10,000-record scan, not a new full public graph export; weighted Axon scheduling and compact CBOR encoding are deferred. The exchange's identity handshake is experimental and requires independent review. Do not enable on sensitive data.
