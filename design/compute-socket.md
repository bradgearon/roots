# Paired compute socket (event-driven)

Android observes default-network callbacks and records a local familiarity fingerprint (IPv4 gateway and subnet, associated with the configured bridge address). This is a preference hint only, not an identity or proof of trust: unrelated networks can share these values. Successful explicit pairing remembers the network; legacy/manual setup can remember the current network. No network discovery or GPS is used. The desktop address is still configured by IP and port (8223).

No scheduled maintenance, idle probes, keepalive pings, or timer-driven reconnects on the compute socket. Network events update routing state and close obsolete sessions. Familiar networks make desktop compute eligible; actual work opens/reuses the encrypted socket, with local fallback on failure. The host permits authenticated idle sessions and imposes a five-second deadline only before the first request. Existing legacy browser sockets retain their own behavior.

Pairing uses the existing desktop key. Start `launch.cmd --lan`, then run `get-key.cmd` to display and copy the key. Save it with the bridge address on the phone. The permanent key is stored using Android Keystore-backed encryption and is never transmitted in plaintext by the compute socket. One-time invitation/client registration has been removed. Familiarity never substitutes for authentication. No audited security claim; integration testing required. Desktop PLaMo only; desktop streaming/discovery still outstanding.
