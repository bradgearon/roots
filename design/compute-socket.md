# Paired compute socket

The Android service keeps one encrypted WebSocket open at the configured desktop bridge URL, /api/compute/v1/socket. The desktop host accepts the upgrade but requires a successful paired-key authenticated probe before accepting inference. Both probe and translation use the existing AES-GCM envelope with separate request/response keys and a response bound to its request nonce. No bearer token or social text is transmitted in plaintext by this route. Legacy routes remain for other clients.

The maintenance executor checks permission, pairing and active Wi-Fi every four seconds, reconnects with backoff and probes the compatible model every twenty seconds while idle. No GPS, Wi-Fi name or IP identity is used. The phone continues to translate locally if the encrypted session is not ready, without waiting for discovery; a busy socket also falls back locally. One outstanding request per socket, no heartbeat queued behind inference. Leaving X no longer tears down the compute connection. Stopping the accessibility service, revoking permission, or changing pairing closes or invalidates it; Android may suspend or kill the process, so this is not a guarantee of always-on connectivity. Connection is re-established when the service resumes.

Initial pairing still requires the existing secret stored in Android Keystore (or a future authenticated pairing UI). Never fetch an untrusted desktop's secret automatically. The desktop must be running with --lan and the configured address reachable. This first version advertises the PLaMo capability, not live GPU load or additional models. No streamed desktop tokens yet. Existing completion latency routing remains intact. No audited security claim; integration testing required.
