# Durable work and promise projection

The authorized Tree owner stores jobs in the existing SQLite database. Work refers to an existing fragment; it does not acquire or transmit content. The unique key is (fragment sequence, operation, profile), with profile including target language and model/prompt revision. Repeated requests promote priority and earliest deadline without repeating completed work. A 40,000-row quota fails explicitly; clear cascades via fragment foreign keys. Terminal jobs are retained until Tree clear.

Workers claim one operation at a time, ordered by descending priority, earliest nonzero deadline, then ID. Claims are atomic across handles. A lease expires and can be reclaimed; tokens fence stale completions. Renew, retry with a ready time, complete, fail and cancel are explicit. Only the owner supplies timestamps. The core has no network, timers or model invocation. It does not yet implement dependencies, cross-fragment deduplication, priority demotion, automatic retry policies, peer transport, or inference integration.

Java and .NET expose the same durable API plus event-driven promise projections. Attach by ID after restart; completion notifications call refresh, reconnect calls refreshAll. A terminal failure/cancellation is returned as a terminal Work record, not a successful translation. Dispose only cancels local waiters. Do not invoke DB calls on the UI thread. Applications must enforce capture, storage, synchronization and processing consent, and drop projections on revocation. No extra acquisition or network transfer is enabled by this change.

Build native Tree (separate from PLaMo brain), run ctest. Future integration: commit observations then enqueue their fragment IDs, provide actual worker capacity and authenticated peer lease requests, dispatch operations and publish completion events. A worker must obtain fragment content using an authorized Tree query/lookup; this foundation does not change the live overlay.
